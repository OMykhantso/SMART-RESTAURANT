**ТЕХНІЧНЕ ЗАВДАННЯ на виконання курсової роботи «Інтернет-проєкт» на тему: «Інформаційна система ресторану SMART RESTAURANT з онлайн-бронюванням, QR check-in, замовленням зі смартфона та оплатою».**

**1.1 Мета роботи.** Розробити клієнт-серверну Web/Mobile інформаційну систему ресторану, яка автоматизує процес «бронювання → підтвердження → check-in → замовлення → приготування → готовність → оплата» та власну службу доставки. Основна проблема, яку вирішує система, — розірваність процесів обслуговування: ручне ведення бронювань, очікування офіціанта й рахунку, паперові чеки на кухні, відсутність статусу для гостя і залежність від сторонніх агрегаторів доставки.

**1.2 Найменування та галузь застосування обʼєкта розробки.** Програмна система SMART RESTAURANT для ресторанного бізнесу. Призначення — онлайн-бронювання столиків, замовлення зі смартфона, робота залу й кухні в реальному часі, оплата та доставка. Категорії користувачів: гості (клієнти), працівники залу (хостес, офіціанти), кухарі, курʼєри, адміністратор. Умови застосування: ресторан із залом на 10–50 столиків і доставкою містом; персонал працює з компʼютера чи планшета, гості й курʼєри — зі смартфона.

**1.3 Підстава для проведення робіт.** Підставою для розроблення програмного забезпечення є навчальний план спеціальності F3 «Комп'ютерні науки», робоча програма навчальної дисципліни «Інтернет-проєкт» та індивідуальне завдання на курсову роботу.

**1.4 Основні вимоги до програмної системи.**

- Бізнес-ролі: клієнт, працівник залу, кухар, курʼєр; технічна роль — адміністратор.
- Web-застосунок: меню, бронювання з планом залу, кабінет гостя, оплата; робоче місце працівника залу (план залу, бронювання, kanban замовлень, сканер QR); kitchen display; адміністрування (меню, столики й QR, користувачі, аналітика).
- Mobile-застосунок: меню, бронювання, QR check-in камерою, замовлення, статус у реальному часі, оплата, доставка з геолокацією, відгуки; робоче місце курʼєра; мобільне робоче місце персоналу.
- Основний наскрізний процес: бронювання → підтвердження → check-in → замовлення → приготування → готовність → оплата; процес доставки: оформлення → оплата → кухня → курʼєр → доставлено.
- CORE: меню, столи, бронювання, замовлення, статуси.
- ADVANCED: booking engine, QR, sandbox payment.

Система повинна бути реалізована за клієнт-серверною архітектурою та містити Web-застосунок, Mobile-застосунок, Backend/API, єдину базу даних, автентифікацію та авторизацію, не менше двох функціонально різних бізнес-ролей, бізнес-логіку предметної області, реальну двосторонню Web/Mobile-інтеграцію та ADVANCED-компоненти відповідно до індивідуального завдання.

**1.5 Вимоги до проєктування.** Сформувати функціональні й нефункціональні вимоги, розробити Use Case Model, Architecture Diagram та логічну модель бази даних із таблицями, атрибутами, PK, FK, звʼязками та кардинальностями.

**1.6 Вимоги до програмної реалізації.** Погоджений технологічний стек: TypeScript; React, React Router, Tailwind CSS (Web); React Native, Expo, React Navigation (Mobile); Node.js, Express, REST API, JWT (Backend); PostgreSQL, Prisma (база даних); Socket.IO (реальний час); Docker, GitHub Actions. Передбачити реалізацію Backend/API, серверної бізнес-логіки, автентифікації, авторизації, контролю доступу, валідації даних, Web- та Mobile-клієнтів. Web і Mobile використовують спільний Backend та єдину базу даних; Mobile не реалізується як WebView або адаптивна версія Web.

**1.7 Вимоги до тестування.** Передбачити тестування основних бізнес-сценаріїв, автентифікації, авторизації, ролей, API, Web, Mobile, Web/Mobile-інтеграції, валідації, помилкових і заборонених операцій та ADVANCED-компонентів; для алгоритмічної функціональності (booking engine, рекомендації, геолокація) — перевірку на контрольних даних.

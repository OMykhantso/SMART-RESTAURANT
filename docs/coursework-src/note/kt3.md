## АНОТАЦІЯ

Звіт до контрольної точки № 3 курсової роботи «Інтернет-проєкт» підтверджує практичне завершення системи SMART RESTAURANT: працездатний мобільний застосунок зі спільною автентифікацією, роботу Web і Mobile через той самий Backend, двосторонню взаємодію Web і Mobile, наскрізні бізнес-процеси, ADVANCED-компоненти та основні результати тестування.

Мобільний застосунок на React Native (Expo) працює з Restaurant API і Delivery API, використовує камеру для QR check-in, геолокацію для доставки та локальні сповіщення. Реалізовано ADVANCED-компоненти теми – booking engine, QR-коди та sandbox-оплату, а також kitchen display, рекомендації, real-time і службу доставки.

У звіті описано архітектуру, реалізацію Web- і Mobile-застосунків та їхню інтеграцію, компоненти підвищеної складності, методику й результати тестування.

## ВСТУП

Темою курсової роботи є інформаційна система ресторану **SMART RESTAURANT** з онлайн-бронюванням, QR check-in, замовленням зі смартфона, оплатою та доставкою. На КТ № 2 продемонстровано комплекс Web + Backend/API + база даних.

Згідно з методичними вказівками на КТ № 3 потрібно продемонструвати працездатний Mobile, спільну автентифікацію, роботу через той самий Backend, двосторонню Web/Mobile-взаємодію, наскрізний процес, ADVANCED-компоненти, основні результати тестування та практично завершену систему. Де саме виконано кожну вимогу:

- працездатний Mobile і спільна автентифікація – підрозділи 2.3 і 2.5 (рис. 2.6–2.9), тест TC-D01;
- робота через той самий Backend і двостороння взаємодія – підрозділ 2.5 (сценарії Mobile → Backend/API → Database → Web і Web → Backend/API → Database → Mobile), тест TC-36;
- наскрізний процес – підрозділ 3.2 (повний цикл у залі та доставка через дві системи);
- ADVANCED-компоненти – підрозділ 2.6 (booking engine, QR, sandbox payment) і контрольні дані в підрозділі 3.1;
- основні результати тестування – розділ 3 (табл. 3.1, табл. 3.2).

## ВИСНОВКИ

На контрольній точці № 3 система SMART RESTAURANT практично завершена. Мобільний застосунок працює з тим самим обліковим записом і тим самим Backend, що й Web: бронювання, створене на телефоні, одразу бачить персонал у Web, а підтвердження працівника залу миттєво змінює статус у мобільному застосунку. Повний цикл у залі та доставка через дві серверні системи проходять від початку до кінця.

ADVANCED-компоненти теми (booking engine, QR-коди, sandbox-оплата) реалізовано й перевірено на контрольних даних. Усі 118 автоматизованих тестів серверної частини проходять для кожного дня тижня, а наскрізні тести в браузері й безперервна інтеграція підтверджують працездатність системи.

Після КТ № 3 залишається оформлення пояснювальної записки, підготовка демонстраційного сценарію та за потреби покращення інтерфейсу.

# 10. Сценарій демонстрації на захисті (≈ 9 хв)

> Перед захистом: `./scripts/setup-https.sh` (один раз — «замочок» без попереджень), `docker compose up -d --build` → **https://localhost:8443** (або `npm run dev`), `cd mobile && npx expo start`, телефон з Expo Go у тій самій Wi-Fi мережі. У Web відкрийте дві вкладки: **гість** і **персонал** — кожна вкладка має власну сесію. Роль офіціанта чи кухаря можна показати і на другому телефоні (кнопки демо-доступу на екрані входу). Роздрукуйте настільні картки з QR («Адміністрування → Столики та QR → Друк усіх QR») або покажіть QR столика на другому екрані.

| Роль | Email | Пароль |
|---|---|---|
| Клієнт | `client@smartrest.ua` | `Client123!` |
| Офіціант / хостес | `staff@smartrest.ua` | `Staff123!` |
| Кухар | `kitchen@smartrest.ua` | `Kitchen123!` |
| Адміністратор | `admin@smartrest.ua` | `Admin123!` |
| Курʼєр | `courier@smartrest.ua` | `Courier123!` |

> Доставка приймає замовлення з відкриття кухні до закриття мінус 45 хв (будні до 22:15). Для демонстрації пізно ввечері: `DELIVERY_IGNORE_HOURS=true docker compose up -d delivery`.

## Сценарій 1 — Web: автентифікація → основна операція → бізнес-логіка
1. Web → «Увійти» → **Офіціант** (кнопка демо-доступу).
2. Дашборд: виручка за день, гості в залі, план залу наживо, «потребує уваги».
3. «Бронювання» → нове бронювання в статусі «Очікує підтвердження» → **Підтвердити**.

## Сценарій 2 — Mobile: автентифікація → дані → мобільна операція
1. Expo Go → «У мене вже є акаунт» → зареєструвати **нового** користувача (показує, що система працює не лише з демо-даними).
2. Головна → «Обрати час» → сьогодні, 2 гостей → найближчий слот → план залу з **рекомендованим** столиком і поясненням → «Забронювати».
3. Екран бронювання: QR-код і код `R-XXXXXX`.

## Сценарій 3 — Mobile → Web
* Щойно створене бронювання **миттєво** зʼявляється у Web (toast + звук + бейдж у меню «Бронювання»).

## Сценарій 4 — Web → Mobile
* Офіціант натискає «Підтвердити» → на телефоні банер «Бронювання підтверджено! 🎉», вібрація, статус змінюється без оновлення.

## Сценарій 5 — Повний бізнес-процес і дві ролі
1. **Check-in:** на телефоні центральна кнопка QR → навести камеру на QR столика (іншого столика — покаже «Ваш столик — №N»). → «Ласкаво просимо!».
2. **Замовлення:** Меню → додати 2–3 страви → кошик показує «Пасує до замовлення» → «Надіслати на кухню».
3. **Офіціант (Web)** → «Замовлення» (Kanban) → «Прийняти».
4. **Кухар (Web)** → Kitchen display → «Почати готувати» → відмітити страви → замовлення автоматично «Готово». На телефоні — сповіщення «Ваше замовлення готове!», кільце ETA.
5. **Офіціант** → «Подано».
6. **Оплата (Mobile):** «Оплатити» → картка `4000 0000 0000 3220` (3-D Secure) → код `123456` → чек. Web отримує подію оплати.
7. **Відгук** → зірки, оцінки страв. **Завершити візит** → столик на плані залу стає вільним.

## Сценарій 6 — Доставка: дві системи, одна база даних
1. **Клієнт (Mobile):** додати страви в кошик → «Оформити доставку» → збережена адреса «Дім» (або «Інша адреса» → район, вулиця, будинок) → видно тариф району, мінімальну суму, «ще N ₴ — і доставка безкоштовна», прогноз ≈ хв.
2. «До оплати» → картка `4000 0000 0000 3220` → код `123456` → «Стежити за доставкою».
3. **Кухар (Web)** → Kitchen display: тікет **«Доставка» · район** зʼявляється сам (подія прийшла з Delivery API через PostgreSQL LISTEN/NOTIFY) → відмітити страви → «Готово».
4. **Курʼєр (другий телефон, кнопка «Курʼєр»):** вкладка «Замовлення» → «Взяти» (можна ще під час приготування) → «Мої» → «Маршрут» / «Подзвонити» → «Забрав замовлення» → «Вручено клієнту».
5. **Клієнт** бачить кожен крок наживо: «Готуємо» → «Готово» → «Курʼєр уже в дорозі 🛵» (імʼя курʼєра, ETA) → «Доставлено» → «Оцінити доставку».
6. **Адміністратор (Mobile)** → «Доставка» (диспетчерська: курʼєри, призначення) → «Зони доставки» (вимкнути район / змінити тариф) → «Аналітика» → блок «Доставка» (частка виручки, середній час до дверей, райони).
7. Показати, що це **окремі сервіси**: `docker compose ps` → `backend` (:4000) і `delivery` (:4100); Swagger кожного — `/api/docs`.

## Сценарій 7 — API
* `http://localhost:4000/api/docs` → Swagger: `GET /api/booking/availability` (без токена), `POST /api/auth/login` → Authorize → `GET /api/reservations/my`.
* Показати формат помилки: `POST /api/reservations` на зайнятий столик → 409 з альтернативами.

## Сценарій 8 — ADVANCED / BONUS
* **Booking engine:** на сайті в бронюванні показати зайняті слоти, «останні N столиків», план залу з рекомендацією та причинами.
* **Гарантія БД:** `psql` → спробувати вставити перетин → помилка `reservations_no_overlap`.
* **Sandbox-платежі:** картка `4000 0000 0000 0002` → «Банк відхилив операцію».
* **Kitchen display, real-time, рекомендації, аналітика** (Адмін → Аналітика: виручка, топ страв, навантаження по годинах).
* **Автотести:** `cd backend && npm test` → 111 тестів (зал + доставка); `npm run e2e` → браузер сам проходить сценарій захисту і доставку (≈ 20 с).

## Готові відповіді на «несподівані» прохання комісії

| Прохання | Що показати |
|---|---|
| Спробувати заборонену операцію | клієнт → `PATCH /reservations/:id/status {CONFIRMED}` у Swagger → 403 `TRANSITION_FORBIDDEN`; офіціант → «Готувати» → 403 |
| Ввести неправильні дані | реєстрація з паролем «123» → повідомлення під полем; бронювання на 22:30 → «Ресторан працює 10:00–23:00» |
| Показати запис у БД | `npx prisma studio` (backend) або `psql` → таблиці `reservations`, `orders`, `status_changes` |
| Пояснити таблицю / endpoint | `docs/05-database.md`, `docs/06-api.md`, Swagger |
| Знайти фрагмент коду | booking engine — `backend/src/modules/booking/engine.ts`; автомати станів (зал і доставка) — `backend/src/lib/stateMachine.ts`; оплата — `backend/src/modules/payments/sandbox.ts`; доставка — `backend/src/delivery/delivery.service.ts`; звʼязок систем — `backend/src/lib/bus.ts` |
| Як дві системи працюють з однією БД | `docs/04-architecture.md` (діаграма і послідовність), таблиці `orders.type`, `deliveries`; спробувати `PATCH :4000/api/orders/:id/status {DELIVERING}` → 409 `USE_DELIVERY_API` |
| Змінити дані й повторити | Адмін → Меню → змінити ціну / стоп-лист → миттєво на телефоні |
